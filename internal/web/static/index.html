Database

All history lives in one local SQLite database — nothing here is sent anywhere. Clearing it wipes connection history, port stats, approved ports, and cached lookups, but keeps your configured firewalls (they'll start repopulating on the next poll).

What this is

ConnTrack polls one or more Cambium NSE3000/4000 firewalls over SSH for their connection-tracking table (show conntrack), stores the history in a local database, and scores connections and ports for risk — so you can see what's actually talking to what, decide what to leave open, and get a reviewable firewall rule list for everything else. It's a standalone companion to NSELocalSSH, reusing its SSH session pattern and connection-tracking data model.

Where the data comes from

  • Connections & the "Application" tag — read directly from your firewall's own DPI classification over SSH. Nothing here is guessed.
  • Risk score — a local, offline heuristic (legacy admin ports, cleartext protocols, unrecognized traffic on an odd port, high-volume first contact, low sample confidence) combined with a cached GreyNoise Community reputation lookup for public destination IPs — free, no account needed, capped at 10 lookups/day, which this app respects by caching aggressively and spreading lookups across the day.
  • "What do we know about this IP" lookups — five free, keyless sources (ipwho.is, RDAP, reverse DNS, Team Cymru ASN, Shodan InternetDB), each individually toggleable in Settings and off by default. Enabled sources are queried together with one click on a destination IP. These are the only things in the app that send anything to a third party outside the GreyNoise reputation check.

The rule preview is deny-only, manual-review

NSELocalSSH's own firewall code marks the device's outbound-filter allow action as unconfirmed over CLI — only deny has proven working syntax. So the Rule Preview tab never generates an allow rule or a catch-all "deny everything else" — only named deny rules for specific ports/applications you haven't approved. Nothing is ever pushed to a device from here; review each row and transcribe it into NSELocalSSH's own Firewall screen yourself.

Multiple firewalls, never merged

Every table is scoped by firewall. Switching the picker at the top never blends one firewall's history, risk scores, or approved-ports list into another's.

About the "Demo Firewall"

If you ever see a firewall called "Demo Firewall" with obviously synthetic traffic (e.g. telnet to 203.0.113.66), that's seeded by a separate developer tool (cmd/replay) used to test this dashboard without a live device — it is not part of the real app. A fresh install of conntrackd or ConnTrack.app always starts with zero firewalls configured until you add one from the Settings tab.
